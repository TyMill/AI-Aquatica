# Real water-quality dataset used in the SoftwareX workflow

`water_quality.csv` is the original dataset used by `examples/real_dataset_workflow.py` and the SoftwareX illustrative example.

## Origin and sampling design

- Study area: urban aquatic systems within Szczecin, West Pomeranian Voivodeship, north-western Poland.
- Monitoring locations: Lake Głębokie, Lake Słoneczne, the inflow to Lake Rusałka, and the outflow from Lake Rusałka.
- Sampling period: January 2020 to January 2023.
- Sampling frequency: monthly.
- Sampling campaigns: 37.
- Observations: 148, with one observation per station in each campaign (37 per station).
- Data ownership: original measurements generated by Tymoteusz I. Miller.
- Data type: real, non-synthetic laboratory and field measurements.
- Personal data: none.
- Spatial disclosure: general site names are disclosed; exact sampling coordinates are not included.

Station codes are mapped as follows:

| Code | Monitoring location |
|---|---|
| r1 | Lake Głębokie |
| r2 | Lake Słoneczne |
| r3 | Lake Rusałka inflow |
| r4 | Lake Rusałka outflow |

## Analytical framework

Analyses were performed using laboratory procedures consistent with relevant EN ISO/ISO water-quality standards. The principal methods were potentiometric pH measurement, electrochemical dissolved-oxygen measurement, permanganate index, sealed-cuvette dichromate COD, five-day BOD, titrimetric determinations of alkalinity, hardness and selected ions, spectrophotometric ammonium determination with Nessler reagent, and atomic absorption spectrometry (AAS) for metals. Chlorophyll-a was determined spectrophotometrically after pigment extraction.

A parameter-level method and unit table is provided in `analytical_methods.csv`. Exact instrument models, detection limits and batch-specific QA records are not distributed with this demonstration dataset.

## Variables and reporting units

| Column | Interpretation | Reporting unit used in the dataset |
|---|---|---|
| Station | coded monitoring location | not applicable |
| month | ordered monthly campaign, 1 = January 2020 and 37 = January 2023 | not applicable |
| Chl_a | chlorophyll-a | µg/L |
| Eh | redox potential | mV |
| Temp | water temperature | °C |
| pH | pH | dimensionless |
| COD_Mn | permanganate index | mg O2/L |
| COD_Cr | dichromate chemical oxygen demand | mg O2/L |
| BOD5 | five-day biochemical oxygen demand | mg O2/L |
| O2_dissolved | dissolved oxygen | mg O2/L |
| Secchi_depth | Secchi transparency | cm |
| NO3 | nitrate reported as nitrogen | mg N/L |
| NO2 | nitrite reported as nitrogen | mg N/L |
| NH4 | ammonium reported as nitrogen | mg N/L |
| TN | total nitrogen | mg N/L |
| SRP | soluble reactive phosphorus | mg P/L |
| TP | total phosphorus | mg P/L |
| TH | total hardness | mg CaCO3/L |
| Ca, Mg, Cl, SO4 | major ions | mg/L |
| Alkalinity | total alkalinity | mg CaCO3/L |
| Acidity | acidity | mg CaCO3/L |
| Fe_total, Mn_total, Pb, Zn, Cd, Cu | metals | mg/L |

For charge-balance calculations, `NO3`, `NO2`, and `NH4` must therefore be converted from the dataset reporting basis (mg N/L), not from mg of the complete ion per litre. The reproducible SoftwareX workflow passes the explicit `NITROGEN_AS_N_MASS_PER_MEQ` conversion mapping to the hydrochemical module.

## Hydrochemical limitation

Sodium and potassium were not measured in the released dataset. Consequently, charge-balance error quantifies closure of the selected available ion set and must not be interpreted as complete conventional major-ion closure. AI-Aquatica reports this limitation during the pre-flight diagnostic.

## Reproducible use

```bash
python examples/real_dataset_workflow.py examples/data/water_quality.csv --output outputs/real_dataset
```

The workflow preserves the original file, writes processed outputs to a separate directory, and records validation configuration and metrics in machine-readable files.
